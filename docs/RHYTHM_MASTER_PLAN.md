Легенда: ✅ готово · 🟡 в работе · ⏳ очередь · 🔮 будущие этапы · 🔀 перенесено

## 1. Продукт
Rhythm — адаптивный планировщик жизни. Визуальный таймлайн задач +
фокус-сессии + журнал состояний + умные подсказки. Дифференциатор против
аналогов: подстройка под энергию и состояние пользователя, а не статичный
тайм-блокинг.

## 2. Гибридная архитектура

### 2.1 Схема
```
              ┌──────────────────────────────┐
              │   Supabase (ЕДИНЫЙ бэкенд)   │
              │  auth.users · PostgreSQL     │
              │  RLS по user_id · Storage    │
              └──────────────┬───────────────┘
                             │
            ┌────────────────┴────────────────┐
            │                                 │
   ┌────────▼─────────┐            ┌──────────▼─────────┐
   │  WEB (React+Vite)│            │  MOBILE (Flutter)  │
   │  Этап 2 — добиваем│           │  Трек M0→M5        │
   │  веб-фичи (экспорт,│          │  Этап 3: BioSync,  │
   │  ИИ-чат)          │           │  виджеты, Push     │
   └───────────────────┘            └────────────────────┘
```

### 2.2 Стек
- **Веб:** React + Vite + TypeScript + Tailwind + Supabase
- **Мобайл:** Flutter (трек M), тот же Supabase
- **Бэкенд:** Supabase — auth, PostgreSQL, RLS, real-time
- **Локальный кэш/офлайн:** веб — IndexedDB/localStorage; мобайл — Hive/Drift
- **Уведомления:** веб — Web Notifications; мобайл — FCM/APNs (M4)

### 2.3 Главный принцип
Одна схема БД, одна продуктовая спека на фичу — два клиента.
Спеки (Mood Journal 2.1, Flow Sessions, Smart Suggestions) — общий контракт.

## 6. Правила против дрейфа (обязательны для обоих треков)
1. **Схема Supabase — единственный источник истины.** Мобильный трек НЕ
   создаёт таблицы/колонки. Нужна миграция → стоп и согласование.
2. **Спеки — общий контракт.** Алгоритмы берутся из спеки, а не
   переписываются «как в веб-коде» (защита от дрейфа TS ↔ Dart).
3. **Дизайн-токены — общий файл.** Цвета состояний, кольцо таймера,
   радиусы, тайминги анимаций идентичны на вебе и в мобильном.
4. **Конфликты синхронизации** решаются одинаково: `updated_at`,
   last-write-wins.
5. **Не дублируем фичу в двух треках одновременно:** обкатка в одном →
   порт в другой.

## 9. Канонические продуктовые принципы (действуют во всех клиентах)
- «3-секундный сенсор состояния», базовый check-in = 2–3 тапа.
- Настроение — сигнал, а не оценка личности; никакого давления.
- Детали, заметки, теги — всегда опциональны.
- Инсайты — только наблюдения с объяснимостью («Почему я это вижу?»),
  без причинно-следственных утверждений и без псевдонауки.
- Приватность by design: строгий RLS, экспорт только по инициативе
  пользователя, полное удаление по запросу.
- Каждый модуль закрывается полным контуром проверок:
  tsc · eslint · prettier · vitest · build (+ E2E, когда появится).
