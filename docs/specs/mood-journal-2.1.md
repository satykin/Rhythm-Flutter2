# UX + продуктовая спецификация — Mood Journal 2.1 (Rhythm)

Гибридная версия на основе спецификаций v1 и v2.
Версия: 2.1 · Статус: готово к поэтапной разработке ·
Приоритет: Этап 2, модуль №3.

## 1. Суть и философия
Mood Journal 2.1 — личный журнал состояний внутри Rhythm. Это не
HR-трекер, не дневник благодарности и не терапевтический чат-бот. Его
задача — с минимальным трением фиксировать текущее состояние,
накапливать контекст и постепенно помогать пользователю замечать
собственные паттерны.

### Ключевой принцип
«3-секундный сенсор состояния, который при желании превращается в более
глубокую рефлексию».
- Настроение — сигнал, а не оценка личности.
- Нет давления «быть позитивным» и нет наказания за пропуски.
- Базовый check-in должен занимать 2–3 тапа.
- Детали, заметки и теги всегда опциональны.
- Данные → контекст → осторожные наблюдения, а не категоричные выводы.
- Модуль является частью Rhythm и связывается с Tasks, Flow Sessions,
  Habits и будущим BioSync.

## 2. Цели продукта
- Создать привычку лёгкого check-in без ощущения обязанности.
- Помочь пользователю видеть историю собственных состояний.
- Связывать настроение с контекстом: задачами, фокусом, привычками и временем.
- Показывать только статистически достаточно обоснованные инсайты.
- Стать источником данных для Smart Suggestions и Rhythm AI на следующих этапах.

## 3. Типы записей и триггеры
| Тип | Когда | Частота | Длительность |
|---|---|---|---|
| Quick check-in | По кнопке «+» / хоткею M в web | В любой момент | 3–10 сек |
| Post-focus | После завершения Flow Session | Опционально | 3–5 сек |
| Morning baseline | Мягкое утреннее напоминание | Не чаще 1/день | 5–10 сек |
| Evening reflection | Мягкое вечернее напоминание | Не чаще 1/день | 15–60 сек |
| Manual deep entry | Journal → Новая запись | Без ограничений | 30+ сек |

Единый Prompt Budget: proactive prompts — максимум 2 в день, не чаще
одного раза в 4 часа и никогда в quiet hours. Post-focus не считается
навязчивым prompt, поскольку возникает в непосредственном контексте
завершённой сессии.

## 4. Структура записи
| Поле | Обязательное | Правило |
|---|---|---|
| score | Да | Внутреннее значение 1–5, не обязано отображаться как рейтинг |
| emoji | Да | Одно из пяти состояний |
| note | Нет | До 500 символов |
| tags | Нет | Контекстные теги, максимум 5 на запись |
| source | Да | manual / post_focus / morning / evening |
| linked_task_ids | Нет | Связанные задачи |
| focus_session_id | Нет | Связь с Flow Session |
| logged_at | Да | Время записи, редактируемое для manual entry |
| updated_at | Да | Для синхронизации и разрешения конфликтов |

## 5. Пять состояний
В интерфейсе это описательные состояния, а не шкала «плохо → хорошо».
| Эмодзи | Подпись | Скрытый score |
|---|---|---|
| 😩 | Тяжело | 1 |
| 😔 | Не очень | 2 |
| 😐 | Нейтрально | 3 |
| 🙂 | Хорошо | 4 |
| ✨ | Поток / подъём | 5 |

## 6. Основной UX: Quick Check-In
Первый экран должен быть предельно простым:
- Тап по состоянию активирует «Сохранить».
- Минимальный путь: выбрать состояние → сохранить.
- «Добавить детали» раскрывает заметку и теги.
- На desktop: hover показывает описание состояния; на touch — long press.
- После сохранения: короткая success-анимация и закрытие.
- Reduce Motion заменяет spring/pulse на простое изменение opacity.

## 7. Детали и теги
- На Phase A используются простые пользовательские теги и небольшой
  набор пресетов. Автоматические теги погоды, календаря и задач не
  являются обязательными для MVP.
- Пресеты: work, meeting, exercise, family, rest, sleep, stress и др.
- Пользователь может добавить собственный тег.
- Максимум 5 тегов на одну запись.
- В следующих фазах система может предлагать контекстные чипы, но
  пользователь всегда подтверждает их выбор.

## 8. Journal — история
Journal — основной экран истории. Аналитика не смешивается с лентой.
- Группировка записей по датам.
- Бесконечный скролл / пагинация.
- Поиск по заметкам и тегам.
- Тап → Detail View.
- Редактирование состояния, заметки, тегов и времени.
- Удаление с Undo toast; дополнительное подтверждение — только для
  записей с содержательной заметкой или связями.

## 9. Detail View — запись в контексте
- Полное содержимое записи.
- Дата и время.
- Заметка и теги.
- Связанные задачи.
- Связанная Flow Session.
- Контекст дня: количество задач, время фокуса, привычки.
- Лента остальных mood-записей этого дня.

## 10. Mood Overview
Отдельный экран аналитики с тремя разделами: Неделя · Месяц · Инсайты.

### 10.1 Неделя — Mood Tapestry
- Основная визуализация — сетка 7 × 3: дни недели × утро/день/вечер.
- Ячейка показывает состояние или остаётся пустой, если данных нет.
  Это предпочтительнее эмоционально давящего графика на основном
  аналитическом экране.
- Тап на день открывает записи этого дня.
- Несколько записей в одном временном слоте: в Tapestry показывается
  последняя, в Journal доступны все.
- Числовой score не является главным визуальным элементом.

### 10.2 Месяц — исследование паттернов
- Распределение состояний по дням недели.
- Связи с тегами.
- Связи с привычками.
- Связи с длительностью фокуса и завершёнными задачами при достаточном
  объёме данных.
- В web допускаются графики и детальные слои; для каждого графика
  обязательна текстовая альтернатива.

## 11. Инсайты: данные, а не магия
Инсайты должны формулироваться как наблюдения, а не как
причинно-следственные утверждения.
- Пример: «За последние 30 дней в дни с прогулками твоё состояние чаще
  было выше обычного».
- Не использовать: «Прогулки делают тебя счастливее».

### Правила достоверности
- Минимум 7 наблюдений для базовых статистических инсайтов.
- Для групповых тегов и привычек желательно минимум 5–7 наблюдений; при
  меньшем объёме инсайт не показывается как надёжный.
- Для числовых факторов использовать корреляцию при достаточном
  количестве пар данных.
- Показывать период и размер выборки.
- При возможности показывать уровень уверенности: низкая / средняя / высокая.
- Максимум 3 активных инсайта.
- Новый proactive insight — не чаще одного раза в 3 дня.
- Отклонённый тип инсайта не повторять некоторое время.

## 12. Гибридный корреляционный движок
Используются два типа анализа.

### A. Категориальные сигналы
Теги, дни недели, привычки и категории задач анализируются через
сравнение распределения/медианы состояния группы с личным baseline
пользователя. Для показа требуется достаточный sample size.

### B. Числовые сигналы
Для факторов вроде focus_minutes, tasks_completed и sleep_hours
используется корреляционный анализ по дневным данным. Для раннего MVP
достаточно порога n ≥ 7 и отсечения слабых корреляций.

```
InsightCandidate = {
  signal,
  period,
  sample_size,
  baseline,
  observed_value,
  effect_size,
  confidence,
  direction
}
```

Любой инсайт обязан хранить объясняемые данные, чтобы пользователь мог
открыть «Почему я это вижу?».

## 13. Интеграции
| Модуль | Связь | Фаза |
|---|---|---|
| Flow Sessions | Post-focus + focus_session_id | B |
| Tasks | Связанные задачи и контекст | B |
| Habits | Корреляции mood × habits | C |
| Smart Suggestions | Мягкие предложения на основе паттернов | D/E |
| BioSync | Сон / стресс / физиологические данные | Этап 3 |
| Rhythm AI | Нарративная рефлексия поверх проверенных данных | Этап 3 |

## 14. Приватность и безопасность
- Настроение и заметки считаются чувствительными пользовательскими данными.
- Строгая изоляция данных по user_id / RLS.
- Экспорт только по инициативе пользователя.
- Полное удаление данных при удалении аккаунта.
- Если реализуется клиентское шифрование заметок, необходимо отдельно
  определить управление ключами и синхронизацию между web, macOS и Android.
- Не заявлять «end-to-end encryption» в публичной политике, пока
  архитектура ключей и синхронизации действительно не обеспечивает это свойство.

## 15. Accessibility и платформенное поведение
- Каждое состояние имеет доступную текстовую подпись.
- Графики имеют текстовую альтернативу.
- Полная клавиатурная навигация в web.
- Web shortcut: M — новый check-in; Enter — сохранить; Esc — закрыть.
- Hover используется только как дополнительный механизм, не единственный.
- Long press используется на touch-устройствах.
- Поддержка screen readers.
- Reduce Motion.
- Адаптивный интерфейс: mobile-first, но desktop не является растянутой
  мобильной карточкой.

## 16. Edge cases
- Нет записей: спокойное onboarding-состояние без давления.
- Несколько записей за короткий период: разрешены, если пользователь
  сделал их вручную.
- Несколько записей в Tapestry-слоте: показывается последняя.
- Редактирование прошлого дня: разрешено, аналитика пересчитывается.
- Удаление данных, на которых основан инсайт: инсайт помечается stale и
  скрывается после пересчёта.
- Смена timezone: хранение timestamptz, отображение в локальном времени.
- Offline: локальная очередь и синхронизация после появления сети.
- Конфликты: стратегия должна опираться на updated_at, а не только на logged_at.

## 17. Метрики успеха
| Метрика | Цель |
|---|---|
| DAU с ≥1 check-in | ≥ 40% |
| Среднее check-in/DAU/день | 1.5–2.0 |
| Completion rate Quick Check-In | ≥ 85% |
| Записи с деталями | ≥ 25% |
| Пользователи, увидевшие первый инсайт после достаточных данных | контролировать |
| Клики «Почему я это вижу?» | контролировать как доверие к инсайтам |
| Недельный возврат в Journal | ≥ 40% |

## 18. Фазы внедрения
| Фаза | Состав | Цель |
|---|---|---|
| A — Core | Quick Check-In, mood_logs, note/tags, Journal, edit/delete, базовая accessibility | Проверить привычку и трение |
| B — Context | Detail View, Tasks, Flow Sessions, post-focus | Добавить смысл и контекст |
| C — Patterns | Mood Tapestry, базовая аналитика, correlations | Показать паттерны |
| D — Retention | Morning/Evening prompts, единый Prompt Budget | Создать мягкий ритм возвращения |
| E — Insights | Достоверные insight cards, feedback, explainability | Вау-эффект без псевдонауки |
| F — Power tools | PDF/CSV export, расширенные фильтры, deep links | Профессиональный уровень |
| Этап 3 | BioSync + Rhythm AI | Глубокая персонализация |

## 19. Что сознательно НЕ входит в Phase A
- OpenWeather и автоматическое определение погоды.
- Автоматическое связывание задач в окне ±30 минут.
- AI-генерация инсайтов.
- Сложные Smart Suggestions.
- PDF-экспорт.
- BioSync.
- Сложная статистическая визуализация.
- Принудительные утренние и вечерние сценарии.

## 20. Итоговая продуктовая формула
Mood Journal 2.1 строится по принципу: «Сначала зафиксировать состояние
за 3 секунды. Потом, если пользователь захочет, добавить контекст. Через
время — показать закономерности. И только после достаточного количества
данных предложить осторожный, объяснимый инсайт».

Это объединяет сильные стороны обеих исходных спецификаций: лёгкость и
дисциплину MVP из первой версии, а также философию, контекстность и
уникальный Mood Tapestry из второй.
